# Глобальное правило безопасности Codex

Управляемый блок для `~/.codex/AGENTS.md`. Добавлять, сохраняя остальные инструкции. Навык в пользовательском `~/.agents/skills/project-security-review/` доступен существующим и будущим проектам данного пользователя.

## Проверка безопасности перед слиянием

- Перед любым слиянием рабочей ветки в главную/защищённую ветку автоматически применяй `$project-security-review`: прочитай `~/.agents/skills/project-security-review/SKILL.md` и нужные references. Это относится к существующим и будущим проектам; объём определяется реальным diff и риском. Для явного полного аудита проверяй весь проект; для новой реализации сначала определи границы доверия.
- До merge проведи анализ кода и применимые проверки безопасности. Подтверждённые нерешённые Critical/High, непринятые владельцем Medium/Low и непрошедшие обязательные проверки блокируют слияние. Недоступную обязательную проверку не называй пройденной. Для документации обоснуй N/A; скрипты, конфигурация и CI — код.
- После финального коммита сохрани локальный отчёт и квитанцию по `references/gate.md`; непосредственно перед разрешённой интеграцией выполни `scripts/security_gate.py verify` для фактических source/target. После изменения коммитов, конфликтов или исправлений актуализируй анализ и проверки. Если навыка/квитанции нет или verify завершился ошибкой — останови интеграцию и назови причину.
- Проверка не заменяет разрешение владельца по `$git-commit`, не запускает субагентов, не устанавливает Git hooks и не защищает ручной Git вне Codex. Серверная CI/защита веток требует отдельной настройки. Не выдавай квитанцию за автоматический поиск уязвимостей или гарантию безопасности.
