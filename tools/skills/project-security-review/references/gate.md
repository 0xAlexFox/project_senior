# Протокол отчёта перед слиянием

Это локальное подтверждение анализа ревьюером. Скрипт проверяет структуру, блокирующие результаты и свежесть коммитов, но не истинность текста отчёта. Не создавай PASS до реального анализа. Обязательность проверок определяют требования проекта и риск изменений, а не удобство запуска.

## Команды

Нужны Python 3.9+ и Git с `--end-of-options`/`--path-format=absolute`. Запускай из чистого worktree после финального коммита. Все локальные данные клади вне tracked-дерева; для worktree используй его собственный Git-каталог. Пример для существующей main и текущей рабочей ветки:

```sh
security_skill="$HOME/.agents/skills/project-security-review"
security_state="$(git rev-parse --path-format=absolute --git-path security-review)"
mkdir -p "$security_state"
python3 "$security_skill/scripts/security_gate.py" scope --base main > "$security_state/scope.json"
```

Команда показывает source/target SHA, merge-base и список файлов, включая изменения целевой ветки после общей базы. Прочитай diff, связанные пути и результаты проверок. Сформируй `report.json` по схеме ниже с объектом `scope` из фактического вывода. Не копируй фиктивные PASS из примера: пример намеренно неполон и не проходит проверку.

```json
{
  "scope": {},
  "manual_review": "Пути, границы доверия, изученные сценарии, ограничения",
  "coverage": [
    {"area": "A01", "status": "na", "evidence": "Причина неприменимости"}
  ],
  "checks": [
    {"name": "Реальная команда или ручная проверка", "required": true, "status": "not_run", "evidence": "Причина отсутствия результата"}
  ],
  "findings": []
}
```

Нужны **ровно десять** coverage: A01–A10, status `pass` или `na`, с конкретным evidence. Проверки: `pass`, `fail`, `not_run`, `na`; boolean `required`. Любой fail блокирует; required требует pass. Необязательные not_run/na сохраняют видимое ограничение с причиной. Пустой список проверок или отсутствие ручного анализа блокируют.

Для каждой finding нужны `id`, `location` (`path:line`), `evidence` (условия/последствия), `confidence`, `severity` (`critical/high/medium/low`), `disposition`. `resolved` требует `verification` с проверкой исправления; `accepted` допустим только Medium/Low с `owner_acceptance` — ссылкой/точной записью прямого ответа владельца о данном риске. Другие случаи блокируют. Пустой findings — явное отсутствие подтверждённых находок в данном объёме; это не результат автоматического сканирования всех классов атак.

```sh
python3 "$security_skill/scripts/security_gate.py" record --base main --report "$security_state/report.json" --receipt "$security_state/receipt.json"
python3 "$security_skill/scripts/security_gate.py" verify --base main --receipt "$security_state/receipt.json"
```

Нулевой exit code — проверка пройдена, ненулевой — BLOCKED. Проверка нужна непосредственно перед разрешённым merge. Можно передать `--repo /path/to/project --head feature/name`; при переключении в целевую ветку обязательно передай реальную source-ветку вместо HEAD. SHA в отчёте должны совпадать. Изменение любой из веток или грязное дерево инвалидируют отчёт; на другом worktree отчёт нужно создать для его Git root. Не подавляй ошибки и не продолжай merge при BLOCKED.

## Полный аудит и первая интеграция

Для полного аудита используй `--mode baseline`, с `--base main`, если она есть. Для обычного pre-merge используй `diff`, не подменяй его старым baseline. Если главная ветка ещё не создана, используй `--mode baseline` **без** `--base`: проверяется всё дерево source, а target=null. Перед отдельно разрешённым созданием main проверь квитанцию с теми же параметрами и фактическое отсутствие целевой ветки. Скрипт не создаёт ветки и не проверяет разрешение владельца.

## Расхождение веток и конфликты

До интеграции оцени сочетание изменений с актуальным target, включая security-инварианты, и проверяй результат совмещения в изолированной рабочей копии, если есть риск взаимодействия. Скрипт блокирует незавершённые merge/rebase и не сертифицирует разрешение конфликтов. Если конфликт возник при разрешённом merge, до завершения проверь разрешённый diff и необходимые тесты вручную; после merge-коммита повтори аудит итогового дерева в baseline и сохрани отдельную квитанцию. Исходный pre-merge отчёт сохраняется. При находке остановись, не объявляй интеграцию успешной.

Квитанции хранят техническое время UTC. Для отчёта владельцу преобразуй его в часовой пояс и формат проекта. Не коммить локальные пути, секреты и полные журналы. Скрипт не устанавливает Git hooks и не защищает удалённую ветку; серверная CI/branch protection — отдельная настройка.
