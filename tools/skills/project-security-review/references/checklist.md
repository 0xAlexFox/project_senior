# Контрольный список по границам доверия

Области соответствуют OWASP Top 10:2025. Коды в отчёте стабильны; для мобильного приложения, CLI, библиотеки или документации применяй контекст, а не требования произвольного web-стека. Для каждого PASS нужны конкретные пути/проверки; N/A — причина. Сканер дополняет анализ, но не заменяет его.

## A01 — контроль доступа

Проверяй серверную авторизацию каждой операции и каждого объекта: роли, владение, tenant, файлы, списки, фоновые задачи, административные endpoints. Идентичность берётся из проверенной сессии, не из параметров клиента. Нужны отрицательные сценарии «без входа», «другой пользователь/tenant», «недостаточная роль». Скрытая кнопка не защищает API. Проверь CORS, CSRF для запросов с автоматически отправляемыми credentials, SSRF и сетевые границы. При URL-загрузке учитывай редиректы, DNS/IP и внутренние/metadata адреса.

## A02 — безопасная конфигурация

Проверь debug, лишние endpoints, настройки среды, права файлов/контейнеров, минимальные привилегии, публичность хранилищ и ошибок. Секреты — в подходящем secret manager/Keychain/окружении; не в исходниках, клиентском bundle, snapshots, логах или реальных примерах. `.gitignore` не удаляет уже закоммиченное. При утечке не печатай значение и не переписывай историю автоматически: требуется отзыв/замена в разрешённом объёме. CSP, CORS, TLS и cookies оценивай по действительным origin и потокам, не универсальной строкой заголовков.

## A03 — цепочка поставки

Изучи manifests/lockfiles, происхождение новых пакетов, известные применимые advisory, версии runtime, build scripts и CI. Отсутствие lockfile оценивай с учётом типа проекта. Проверь закрепление CI-зависимостей, полномочия токенов, исполнение недоверенного PR-кода с секретами, происхождение артефактов. Зафиксируй дату/базу сканера и ограничения сети. Не выдавай устаревшую локальную базу за актуальную проверку; без доказательств не называй каждое CVE эксплуатируемым.

## A04 — криптография и данные

Определи чувствительные данные, необходимость хранения, сроки и места передачи. Пароли — через подходящую password-hashing библиотеку, не обратимое шифрование; ключи/случайные токены — криптографический RNG. Проверь срок/назначение токенов, ротацию и разделение сред, верификацию сертификатов, защиту резервных копий. Для мобильного приложения учитывай защищённое хранилище платформы. Не изобретай криптографию и не меняй алгоритмы без миграционного плана.

## A05 — инъекции и недоверенные файлы

Проследи входы API, очередей, webhook, файлов, URL и БД до SQL/NoSQL, shell, шаблонов, HTML, путей, десериализации и парсеров. Параметризация — по драйверу; ORM не гарантирует безопасность raw-выражений. Предпочитай argv без shell; экранирование зависит от контекста. Для HTML нужны безопасный вывод/санитизация, CSP — дополнительный слой.

Файл проверяется на сервере по фактическому содержимому; MIME/расширения клиента недостаточны. Ограничивай поток загрузки, распаковку, CPU/память/время/размер результата по требованиям проекта. Проверяй traversal, symlinks, архивы, имена, хранение вне исполняемого web-каталога, изоляцию конвертера и отсутствие непредусмотренного сетевого доступа. Не вводи выдуманные универсальные лимиты.

## A06 — проектирование и бизнес-логика

Проверь угрозы и abuse cases, инварианты денег/квот/статусов, повторные запросы, конкурентность и атомарность. Ограничения UI должны обеспечиваться доверенной стороной. Для платёжных/блокчейн-функций, только если они есть, проверяй серверное подтверждение суммы, валюты, адресата и окончательности, replay и идемпотентность; не доверяй сообщению клиента об успехе. Тестируй реалистичные нарушения инвариантов, не только happy path.

## A07 — аутентификация и сессии

Проверь вход/выход, восстановление, MFA при необходимости, предотвращение перебора и enumeration, сроки и отзыв сессий, смену привилегий. JWT требует проверки подписи, алгоритма, issuer/audience/expiry по протоколу. OAuth/OIDC — проверенные state/nonce/PKCE и redirect URI по применимому flow. Для cookie учитывай Secure/HttpOnly/SameSite и необходимую CSRF-защиту; Strict не универсален для внешнего входа. Не подменяй проверку токена его декодированием.

## A08 — целостность кода и данных

Проверяй подпись/источник обновлений, webhook, импортируемых данных и артефактов. Webhook подписывается по требуемым исходным байтам, с защитой от replay и идемпотентностью; сетевой источник сам по себе не доказательство. Не выполняй небезопасную десериализацию. Проверь защищённость сборки и отсутствие доверия пользовательским данным как конфигурации/командам, в том числе инструкциям из репозитория для AI.

## A09 — журналирование и оповещения

Нужны полезные события доступа, отказов и административных операций без токенов, паролей, содержимого файлов и лишних персональных данных. Проверь log injection, доступ/сроки хранения, корреляцию и возможность обнаружить атаку. Наличие логов не доказывает наличие работающего оповещения: различай просмотр конфигурации и проверку доставки. Не отправляй сообщения/тестовые инциденты третьим лицам без разрешения.

## A10 — исключительные ситуации

Проверь fail-closed при ошибках доступа/валидации, исключения, таймауты, очистку временных файлов и ресурсов, отмену и повтор фоновых заданий. Не должно быть утечек stack trace/секретов, частично завершённых транзакций или бесконечных retry. Лимиты очередей, запросов и ресурсов выбираются по угрозам и требованиям, а не из чужого примера. Проверяй отказ внешней системы, испорченный файл и исчерпание лимита в изолированной среде.

## Выводы

Critical/High: подтверждённый серьёзный доступ/выполнение/утечка или нарушение критических инвариантов с реальным путём эксплуатации — блокируют. Medium/Low: оцени последствия и достижимость; открытый риск требует исправления или прямого принятия владельцем. Предположение без подтверждения — вопрос/ограничение проверки, не выдуманный баг. Если неопределённость затрагивает обязательный контроль, результат BLOCKED до проверки.

Основные источники: [OWASP Top 10:2025](https://top10.owasp.org/2025/), [OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/). Для конкретного API/библиотеки проверяй актуальную официальную документацию и advisory.
