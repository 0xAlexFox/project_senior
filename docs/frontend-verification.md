## Фактическая проверка

Установленный Google Chrome на macOS через Playwright, один worker и один временный Vite-сервер. Browser-плагин в этой сессии недоступен; использован обычный Playwright по навыку frontend-testing-debugging. Чистая установка зависимостей заново не выполнялась; граф не менялся после настройки окружения в этой итерации.

Матрица 11 основных страниц: обе темы × 360/390/768/1440 px × текст 100/200% = 176 проверок геометрии. Дополнительно 32 состояния × обе темы × 360/1440 px × текст 100/200% = 256 проверок. Это 432 сочетания в четырёх E2E-тестах, а не 432 независимых пользовательских сценария.

Состояния включают ожидание/прерывание передачи, queued/running/offline/cancelled/failed/succeeded/expired, потерянный ответ и квоту; loading/error/пустой каталог/пустой поиск/удаление; reauth/однократный ключ/маску/отзыв; Telegram/коды/удаление аккаунта/несохранённые изменения; ошибку регистрации/коды; challenge/неверный код/reset/успех; истечение сессии. Остальные отрицательные границы и переходы проверяются отдельными unit/E2E.

Проверяется отсутствие горизонтального скролла страницы и ошибок JS/консоли, видимость заголовков, клавиатурный переход, фокус внутри native dialog, обе палитры и reduced-motion. Для reduced-motion дополнительно проверяется отсутствие работающих Web Animations в матрице страниц; это не инспекция всех внутренних анимаций браузерных контролов. Увеличение текста — CSS font-size 200%, отдельно от изменения viewport. Скриншоты сохраняются при `FRONTEND_QA=1`; локальные PNG/JSON и полные логи находятся в `.local/frontend-completion/`, в Git не входят.

Итоговые команды: `npm run check`, `npm run build:web`, `npm run test:unit:web`, `npm run test:e2e`, `npm run audit:dependencies`. Итог после последних исправлений: check/build PASS, unit 28, E2E 66, audit — 0 уязвимостей. Сохранены 184 финальных PNG и четыре JSON-матрицы (432 сочетания); промежуточные лишние снимки удалены. Просмотрены в том числе узкий экран восстановления с текстом 200%, success, диалог reauth с текстом 200% и API-docs mobile.

## Сверка с Pixso и исправления

MCP после перезапуска фактически прочитал документ, а не только индикатор подключения. Инвентаризация: пять страниц, 192 кадра, 30 компонентов, 16 переменных. Макет не изменялся. Кадр файлов 4:815 ошибочно назван кавычкой; для сверки использовано его содержимое.

Просмотрены целевые кадры главной/входа, кабинета/настроек, JobCard и success, регистрации/кодов/восстановления/reset, файлов/ключа, API-docs/privacy/404. D2C использован как отдельный локальный референс; его package.json и структура не заменяли проект. Уточнены Tabs 52 px с кнопками 48 px, заголовок панели 20 px, композиция 404 и ширина Privacy. Все страницы сняты в двух темах на desktop/mobile; отдельные сложные состояния и текст 200% сохраняются дополнительно.

Найдены и исправлены: длинный заголовок восстановления расширял карточку при 360 px и тексте 200%; отсутствовал текст StatusBadge из-за неверного вызова; вертикальная форма регистрации нуждалась в stack; новый File мог быть заменён прежней завершённой задачей при возврате; уточнены dynamic focus, Escape меню профиля, связанный recovery tabpanel и перестроение вкладок при увеличенном тексте. Нестабильный тест Back получил явное ожидание завершённого SPA-перехода.

Осознанные отличия от статических кадров: обязательные demo-баннер/панель сценариев, более полные тексты ошибок/лимитов и данных, 21 fixture для настоящей пагинации по 20 вместо четырёх показательных строк, актуальные синтетические даты/размеры, расширенный выбор часовых поясов. Точные динамические высоты определяются содержимым. Попиксельный diff всех 192 кадров не выполнялся.

## Границы готовности

Это полностью предварительный frontend. Обычный вход без учебного режима остаётся безопасной заглушкой. Флаг viewer — переключатель демонстрации, не токен/авторизация. File и credentials не отправляются; sample PNG/JPEG/PDF не получены из выбранного исходника. Учебные каталог, профиль, ключ и challenge живут в памяти и сбрасываются при reload; только ограниченные флаги и подтверждённый синтетический job могут восстанавливаться из sessionStorage.

Настоящие доступ/сессии/CSRF, уникальность логина, Argon2id/словарь распространённых паролей, криптографические коды, Telegram, очередь/квота/идемпотентность в БД, проверка байт/изоляция конвертации, приватное скачивание и физическая очистка — будущие серверные TASK-00–06. Нагрузочные цели и выпуск не подтверждены. Screen reader, физические телефоны и другие браузеры не испытаны; автоматического заявления соответствия WCAG нет.

Целевые security-проверки записаны после каждого чувствительного пункта в журнале. Итоговый локальный pre-merge отчёт и квитанция связываются с финальным коммитом по [процессу безопасности](security-review.md). Квитанция проверяет полноту/свежесть записи, а не гарантирует отсутствие уязвимостей. Слияние требует отдельного разрешения владельца на этот результат.
