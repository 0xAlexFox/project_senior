## Начальный frontend — IT-0017

В пределах первых пунктов единого плана подготовлены запуск web, палитры и токены, локальный Inter, базовые кнопки/поля/сообщения/значки и общая оболочка. Главная реализует выбор/замену/удаление одного файла, drag-and-drop, три направления, предупреждения и клиентские UX-проверки формата/размера. Файл сохраняется в памяти при переходе на вход и назад; после reload выбирается повторно. Страница входа валидирует поля и показывает/скрывает пароль; отправка данных и создание сессии отсутствуют. Прочие маршруты — заглушки, не реализованные страницы продукта.

Пункты плана 1–7 выполнены в объёме двух целевых страниц; пункт 8 покрыт только состояниями выбора/ошибок без загрузки/очереди/результата; пункт 9 — только формой входа. Общие компоненты и проверка пункта 16 ограничены этими страницами. TASK-00–06 целиком не завершены.

Фактические проверки: сборка Vite, формат исходников, документация; 10 e2e-тестов Chrome одним worker. Проверены `/` и `/auth/login` в обеих темах на 360/390/768/1440 px и с текстом 200%; переходы, выбор файла на границе размера и превышение на байт, несколько/пустой/несовместимый файл, длинное имя и drag-and-drop, сохранение File только до reload, мобильное меню, базовая клавиатура и отсутствие отправки credentials. Тесты используют искусственные байты и не подтверждают обработку реальных изображений/DOCX. Консоль desktop/mobile — без ошибок и предупреждений приложения; скриншоты просмотрены. Встроенный браузер недоступен (`browser access host is unavailable`), поэтому использован установленный Chrome через Playwright.

Визуальные отличия от Pixso: межстрочный интервал заголовка и некоторые подписи соответствуют действующей текстовой спецификации, поля входа пустые вместо заполненных примеров; добавлены предусмотренный спецификацией текст о хранении и явная пометка предварительной версии. Публикация не выполнялась. Детали — [IT-0017](history/IT-0017-frontend-foundation.md).

## Проверка формы входа — IT-0018

Применён `project-security-review` к текущей странице входа и связанным UI, маршрутам и конфигурации web. Найдены и исправлены два Low-несоответствия REQ-08: заглавные ASCII-буквы логина отклонялись, Unicode-длина пароля считалась как UTF-16. Теперь регистр логина не влияет на допустимость, пароль проверяется по кодовым точкам Unicode без обрезки/нормализации. Добавлены запрет spellcheck/autocorrect/autocapitalize для показанного пароля и возврат к скрытому вводу после отправки заглушки. Ошибки появляются при отправке и уходе из изменённого поля.

Это проверка frontend-заглушки, а не работающей авторизации. Серверная нормализация/уникальность логина, Argon2id, cookie-сессии, CSRF, ограничение перебора, нейтральные ответы и восстановление доступа по-прежнему требуют реализации backend и отдельных проверок. Итоговый набор — 36 браузерных тестов PASS, включая 26 целевых сценариев входа; сборка и npm check PASS, npm audit — 0 уязвимостей. Новые серверы не запускались, существовавший до проверки процесс сохранён. Подробности охвата десяти областей, воспроизведения и результатов — [IT-0018](history/IT-0018-login-security-review.md).

## Семантическая форма конвертера — IT-0020

Карточка конвертера оформлена как form с @submit.prevent, основное действие — button type=submit вместо ссылки. Один обработчик проверяет canContinue и переводит гостя на `/auth/login`; файл остаётся только в памяти SPA. Вспомогательные кнопки имеют type=button. Нативная отправка/перезагрузка и передача байт не добавлены; реальная конвертация и авторизация по-прежнему отсутствуют. Проверки и целевое ревью безопасности — [IT-0020](history/IT-0020-converter-form.md).
