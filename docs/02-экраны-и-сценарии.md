# Экраны, блоки и сценарии

Версия 0.3 · 19 ноября 2026 г. · Основные правила и числа: [ТЗ](01-техническое-задание.md).

Зависимости реализации: [архитектура](06-архитектура-приложения.md), [модель данных](07-модель-данных.md), [задачи и приёмка](05-план-и-приёмка.md). Правила и численные лимиты задаёт ТЗ; схемы внешнего API — [OpenAPI](../api/openapi.json).

## 1. Визуальная система

Оформление задаёт [DESIGN.md](../DESIGN.md): тёмный холст, графитовые рабочие поверхности, матовая верхняя навигация, белая основная кнопка и янтарно-синий градиент главной. Это адаптация предоставленного текстового референса Dimension под наш продукт; прежний светлый дизайн больше не используется.

DESIGN.md — источник визуальных токенов, размеров, адаптивной сетки, компонентов и состава будущих кадров Pixso. Этот документ определяет адреса, действия и состояния. Продуктовые правила и численные лимиты берутся из ТЗ, контракты — из API. При изменении внешнего вида обновлять DESIGN.md и затронутые визуальные указания здесь, не копировать палитру в каждую задачу.

Desktop от 1200 px: контент max-width 1200 px, главная в две колонки; внутри кабинета боковое меню 208 px. На 768–1199 px главная становится одноколоночной, меню кабинета переносится над содержимым. Ниже 768 px: одна колонка, меню по кнопке, библиотека карточками; поля и действия не меньше 44 px по высоте. При 360 px и тексте 200% нет перекрытий и горизонтального скролла страницы. Детальные токены и состояния определены в DESIGN.md.

Не добавлять кнопки без сценариев MVP: AI, платные планы, команды, общая библиотека, избранное и корзина отсутствуют. Макет Pixso ещё не создавался.

## 2. Карта адресов

| URL | Доступ | Содержание |
| --- | --- | --- |
| `/` | Все | Конвертер, вкладки «Изображения» / «Документы» |
| `/auth/login` | Гость | Вход |
| `/auth/register` | Гость | Регистрация и получение резервных кодов |
| `/auth/recover` | Гость | Запрос и ввод кода Telegram либо резервного кода |
| `/auth/reset` | Ограниченная reset-сессия | Новый пароль |
| `/account` | Вход | Обзор, настройка сохранения и ссылки в разделы |
| `/account/files` | Вход | Библиотека сохранённых результатов |
| `/account/api-key` | Вход | Выпуск/замена/отзыв ключа |
| `/account/settings` | Вход | Личные данные, пароль, Telegram, коды, удаление аккаунта |
| `/api-docs` | Все | Документация внешнего API |
| `/privacy` | Все | Понятное описание обработки и удаления данных |
| Неизвестный адрес | Все | 404 со ссылкой на главную |

Вход возвращает только на разрешённый внутренний адрес приложения; не принимать произвольный redirect URL. Для вошедшего пользователя страницы входа/регистрации ведут в кабинет. Недействительная reset-сессия на `/auth/reset` ведёт к восстановлению с пояснением.

## 3. Общая оболочка

| Блок | Сценарий и состояния |
| --- | --- |
| Шапка | Плавающая верхняя панель в потоке страницы; название ведёт на `/`, ссылки на конвертер и документацию API. Гость видит «Войти», вошедший — «Кабинет» и меню профиля с выходом. На auth-экранах упрощённая шапка. Нет глобального поиска |
| Навигация кабинета | Только на закрытых страницах: «Обзор», «Мои файлы», «API-ключ», «Настройки». На desktop слева, на планшете над контентом, на mobile в раскрываемом меню. Гость направляется ко входу. Активный пункт обозначен подложкой, текстом и aria-current |
| Контекстная помощь | Лимиты, предупреждения и время хранения рядом с формой конвертации; ссылка на API в поясняющем блоке. Отдельная постоянная правая колонка не требуется |
| Системные состояния | Баннер потери сети; уведомление об истечении сессии; ошибка сервиса с requestId. Уведомление не перекрывает основное действие и не исчезает раньше, чем пользователь прочёл критическую ошибку |
| Подвал | «О файлах и конфиденциальности», версия приложения при наличии, ссылка на API. Контакт поддержки заполняется владельцем до публичного выпуска, вымышленный адрес не публикуется |

## 4. Главная `/`

Проверять размер и формат по конфигурации сервера. Дополнительные ограничения на пиксели/длину стороны и параметры внутреннего архива DOCX в интерфейс не добавляются.

| Блок | Что содержит | Сценарий |
| --- | --- | --- |
| Заголовок | «Конвертация файлов», краткая цель | Пользователь понимает поддерживаемые возможности без регистрации |
| Выбор инструмента | Две вкладки; в изображениях направления JPG → PNG и PNG → JPG, в документах DOCX → PDF | Смена направления проверяет совместимость текущего файла. Если он несовместим, запросить замену, не удалить молча |
| Зона загрузки | Кнопка выбора, drag-and-drop, допустимые типы/размер | Вся функция доступна клавиатурой, не только перетаскиванием. Для нескольких файлов — ошибка, не скрытый выбор первого |
| Карточка файла | Имя как текст, размер, определённое направление, «Заменить», «Убрать» | Показать длинное имя с переносом/доступным полным значением. Удаление выбранного файла не удаляет ничего из профиля |
| Сохранение | Для вошедшего — фактическое значение настройки и ссылка изменить её в кабинете; для гостя — пояснение про временное скачивание | Настройка не меняется случайно вместе с выбором файла. Предупреждение о белом фоне PNG → JPG расположено до кнопки запуска |
| Основное действие | «Конвертировать» / «Войти и продолжить» | Неактивно без корректного файла. Вход в той же SPA сохраняет выбранный File в памяти; после полного reload нужно выбрать заново |
| Активная задача | Прогресс загрузки, далее очередь/обработка, время, «Отменить» | После принятия можно уйти в кабинет и вернуться; задача восстанавливается по серверному ID. Не запрашивать доступ к файловой системе ради восстановления |
| Результат | Имя/формат/размер, предупреждения, «Скачать», «Конвертировать другой файл» | Для временного результата указать абсолютное время удаления и оставшийся срок; для постоянного — «Сохранено в профиле» и ссылку |
| Ошибка | Понятное сообщение, действия, раскрываемый код/requestId | Не сбрасывать исходный выбор при сетевой ошибке. Повтор после детерминированной ошибки предлагает заменить файл |

Успешное скачивание не должно очищать файл в профиле или автоматически запускать новое задание. Начатое браузером скачивание отображается как «Скачивание начато», без недоказанного «Файл сохранён на вашем устройстве».

## 5. Авторизация

### Вход

Логин, пароль с переключателем видимости, кнопка входа, ссылки регистрации/восстановления, область общей ошибки. Автозаполнение username/current-password. Валидация при отправке и после ухода из изменённого поля; не показывать красные ошибки в ещё нетронутой форме. Во время запроса одна активная отправка; возврат ошибки сохраняет логин, пароль остаётся только в памяти формы. Вставка пароля разрешена.

### Регистрация

Имя, логин, пароль, подтверждение пароля; требования заранее, сообщение о занятом логине, ссылка на описание данных. Серверная уникальность окончательна. Следующий экран показывает резервные коды один раз, действия копирования/сохранения и подтверждение ознакомления. Переход в кабинет возможен после подтверждения. Telegram предлагается привязать в настройках, это не обязательный шаг регистрации.

### Восстановление

Два режима: Telegram / резервный код. После ввода логина показывается нейтральное подтверждение. Затем поле кода, таймер до повторной отправки, сообщение о сроке, кнопки проверить/получить новый. Неверный, просроченный и использованный код объясняются, но не раскрывают сведения о чужом аккаунте. Истечение попыток завершает challenge, не блокирует навсегда сам аккаунт.

При потере Telegram предложить резервный код, а не новый Telegram username. Экран нового пароля доступен только reset-сессии; после успеха сообщить об отзыве сессий/API-ключа и необходимости войти. Пароль и код нельзя помещать в адрес страницы.

## 6. Кабинет `/account`

Приветствие; ссылки «Мои файлы» и «API-ключ»; использование 100 файлов / 500 MiB с учётом резервов; активные задачи с их серверными статусами; переключатель сохранения и текст «Изменение действует только для новых задач. Уже сохранённые файлы останутся».

Переключатель сохраняется отдельным запросом; до ответа виден статус сохранения, при ошибке вернуть подтверждённое сервером значение и показать повтор. Два параллельных клика не отправляют гоняющиеся PATCH. Конфликт версии не перезаписывать автоматически. Пустой кабинет содержит действие «Начать конвертацию»; это не ошибка.

## 7. Файлы `/account/files`

Блоки: заголовок/квота; поиск по имени; фильтр итогового формата PNG/JPG/PDF и источнику web/API; сортировка по дате, по умолчанию новые сверху; список/таблица; пагинация по 20; состояния загрузки/ошибки/пустого списка.

Строка: имя, формат, размер, дата, источник, «Скачать» и «Удалить». Для мобильного — карточки. Превью содержимого не обязательно. Поиск и фильтры синхронизированы с query URL без приватных имён файлов в параметрах: текстовый поиск остаётся в локальном состоянии страницы; в URL только формат/источник/страница/сортировка. На поиске задержка 300 мс, предыдущий запрос отменяется; старый ответ не затирает новый.

Удаление требует диалога с именем файла и пояснением, что вернуть через интерфейс нельзя. После подтверждения сервер немедленно закрывает доступ, строка удаляется только после ответа; при ошибке остаётся с повтором. При закрытии диалога фокус возвращается на исходную кнопку; если строка удалена — на следующую строку либо заголовок списка. Последний элемент на странице удалён — перейти на предыдущую существующую страницу.

## 8. API-ключ `/account/api-key`

Блоки: назначение ключа; текущее состояние (нет/активен/отозван), маска, дата выпуска и последнего использования; выпуск/замена/отзыв; инструкция безопасного хранения; ссылка на документацию. Полный ключ существует в интерфейсе только после успешного выпуска. При навигации/выходе очистить его из памяти; не восстанавливать из localStorage.

Замена и отзыв требуют повторного ввода пароля и подтверждения последствия: старые интеграции перестанут работать. После замены нет возможности «показать прежний». При сбое ответа после успешного создания не пытаться вернуть недоступный секрет из БД: показать маску/состояние и предложить явно выпустить новый ключ.

## 9. Настройки `/account/settings`

| Раздел | Сценарий |
| --- | --- |
| Личные данные | Имя и часовой пояс; неизменяемый логин показан отдельно; сохранить/отменить, защита несохранённого ввода при уходе |
| Пароль | Текущий, новый, подтверждение; ясный результат и завершение остальных сессий |
| Telegram | Статус привязки; подключение с шагами «Открыть бота → Подтвердить в боте → Подтвердить здесь»; срок challenge, смена и отключение |
| Резервные коды | Осталось N, выпуск нового набора после пароля; старые аннулируются, новые видны один раз |
| Удаление аккаунта | Отдельная опасная зона, пароль и явное подтверждение; описание удаления файлов/ключа/сессий и срока очистки копий |

Безопасность является частью сценариев: ошибка Telegram не мешает сохранить отображаемое имя; истёкшая проверка пароля запускает повторную проверку только для опасного действия. Не предлагать пользователю прислать пароль или документы в поддержку.

## 10. Документация `/api-docs`

Оглавление; получение ключа; таблица трёх направлений; лимиты и временное хранение; последовательность upload → status → download; параметры и коды ошибок; curl/Node.js; правила повтора/отмены; ссылка скачать OpenAPI. В примерах только переменная окружения, реального ключа пользователя на странице нет. Интерактивная отправка секретов из браузера в MVP не нужна.

Страница доступна без входа, но это не означает анонимный доступ к `/api/v1`. «Скачать OpenAPI» отдаёт JSON контракта, без ключей и внутренних адресов. Текст и код доступны клавиатурой, копирование подтверждается только фактически.

## 11. Сквозные сценарии для макета и разработки

1. Гость выбирает DOCX → видит лимит/предупреждение → входит → запускает → видит очередь → получает PDF и срок скачивания.
2. Пользователь включает сохранение → отправляет JPG → во время обработки выключает переключатель → этот PNG остаётся сохранённым, следующий результат временный.
3. Программа отправляет PNG с `save_to_profile=false` → получает job ID → опрашивает статус → скачивает JPEG с белым фоном.
4. Сеть пропала после загрузки → интерфейс показывает неизвестный статус → связь вернулась → тот же job, без повторной конвертации.
5. Пользователь забыл пароль → подтверждает через ранее привязанный Telegram/резервный код → задаёт пароль → входит → выпускает новый API-ключ.
6. Пользователь пытается скачать чужой ID, просроченный файл либо файл после удаления → сервер не выдаёт содержимое, интерфейс показывает соответствующее безопасное состояние.

По [плану макета в DESIGN.md](../DESIGN.md#11-план-будущего-макета-pixso) подготовить desktop/mobile главной, кабинет/файлы/ключ/настройки, все auth-экраны, документацию, состояния upload/queued/running/success/error/offline/empty, диалоги удаления и замены ключа. Сейчас этот документ — инструкция для макета, не утверждение о его создании.
