## Задача и результат

По запросу владельца подготовлены только структура, зависимости и базовые декларативные настройки. Созданы manifests шести приватных npm workspaces, единый lock, пустые каталоги по архитектуре и корневые настройки npm/Node, редактора, форматирования, Docker context и локальной PostgreSQL. Исходники JS/Vue/HTML/CSS/SQL, примеры, миграции, фиктивные точки входа и конфигурации JS не добавляются. Существующие инструменты Python и контракт OpenAPI сохранены.

Точный состав, команды и версии — [подготовка окружения](../project-setup.md). Зависимости сверены с npm registry и официальной документацией через Context7; Node.js 24.19.0/npm 12.0.2 доступны на рабочей машине. Установка выполняется по lock без lifecycle scripts. Новые зависимости не устанавливаются глобально.

Аудит первого дерева выявил шесть Moderate-уведомлений через glob/minimatch. Вместо audit fix --force добавлены адресные overrides glob 14.0.6 и minimatch 11.0.9 для уязвимого диапазона. Из-за сохранения npm прежнего nested-resolution lock заново разрешён в отдельном каталоге только manifests; чистое разрешение сообщило zero vulnerabilities. Проверяются реальные потребители изменённых API, а не только наличие записи в lock. Необходимость overrides описана в инструкции; полноценные миграции с БД по-прежнему относятся к TASK-01.

Compose закрепляет PostgreSQL 18.7-bookworm по официальному multi-platform digest, loopback-порт, постоянный volume по правилам PostgreSQL 18 и обязательный пароль. Локальный `.env` создан с отдельным случайным паролем, mode 0600; значения не выводятся и не входят в Git/контекст Docker. Пользователь bootstrap-БД не предназначен для будущего API/worker: ограниченные роли будут созданы на TASK-01. `.env.example` и тестовые данные не создаются.

README, архитектура, решения по технологиям, статус, Git-процесс и TASK-01 актуализированы: подготовка структуры не означает выполнения TASK-00/01. В памятке нового web-проекта добавлен раздел 4.1 о подготовке без исходников; версия 0.6, уточнён чек-лист выбора генератора. Глобальные инструкции и установленные навыки этой итерацией не менялись.

## Проверка

Необходимый набор: чистая npm ci с запрещёнными install scripts; npm ls/engines/peer dependencies; npm audit полного дерева; формат декларативных файлов; проверка Markdown/OpenAPI и отдельной переносимой копии; JSON Schema Compose и проверка loopback/digest/volume/секретов; загрузка серверных нативных пакетов и инструментов; совместимость glob/editorconfig/js-beautify/node-pg-migrate после overrides; финальный diff/индекс и отсутствие новых исходников/примеров.

Чистая финальная установка: 327 npm-пакетов добавлено, 334 записи проверено, zero vulnerabilities. `npm run check` — PASS; полный npm audit — zero vulnerabilities. Проверка Sharp/libvips, Argon2 bindings, pg/pg-boss и регистрации выбранных Fastify-плагинов — PASS без listen/подключения к БД. Совместимость migration glob, beautifier globSync, editorconfig и Vue Test Utils/jsdom в памяти — PASS; файлы fixtures не создавались. Compose соответствует официальной JSON Schema, digest/loopback/volume и права локального `.env` проверены.

Полные фактические результаты, временные проверяющие программы и метаданные находятся в `.local/project-foundation/` вне Git. Временные программы не являются исходниками приложения и не поставляются с подготовленной структурой. При проверке npm используется штатный TLS: системный Python не смог проверить цепочку сертификатов registry, поэтому получение метаданных перенесено на npm без отключения верификации.
