# IT-0012 — глобальная проверка безопасности перед слиянием

Дата: 20 ноября 2026 г.
Поисковые слова: безопасность, security-review, ECC, OWASP, глобальный навык, merge, отчёт.

## Задача и результат

По прямому запросу владельца создан `$project-security-review` на основе ECC security-review с сохранением MIT-уведомления и фиксацией upstream commit. Переносимые исходники — [tools/skills/project-security-review](../../tools/skills/project-security-review/SKILL.md). Примеры конкретного web-стека заменены проверками применимости; добавлены десять областей OWASP Top 10:2025, доказательства находок, границы доверия и запрет выдавать непроверенное за PASS.

Навык установлен в `~/.agents/skills/project-security-review/`. В `~/.codex/AGENTS.md` добавлен управляемый блок, в глобальные Git-навык, workflow и правила проверки — обязательный аудит перед merge. Подготовленные изменения просмотрены до установки; предыдущие файлы сохранены в `.local/security-review-setup/backups/`, исходные хеши и ожидаемые результаты — в локальном manifest. Прочие инструкции сохранены. Установленные восемь файлов навыка и четыре изменения глобальных инструкций сверены побайтно/по SHA-256; отключающей настройки для нового навыка не обнаружено. Системные службы, hooks, удалённые настройки и права не менялись.

`security_gate.py` проверяет полноту локального отчёта и соответствие точным source/target SHA, merge-base и diff; отклоняет грязное дерево, незавершённые операции, устаревший отчёт и блокирующие результаты. Это не сканер уязвимостей и не защита ручного Git вне Codex. Наличие текста принятия риска в отчёте не доказывает согласие: его обязан сверить ревьюер. Протокол и ограничения — [порядок безопасности](../security-review.md).

Обновлены инструкции проекта, Git-процесс, навигация/статус и памятка будущих проектов. Исходники включены в историю репозитория; глобальные личные файлы и полные логи в Git не добавлены. Приложение и Pixso не изменяются и заново не проверялись.

## Проверки

- 12 unittest-сценариев с реальными временными Git-репозиториями — PASS как для исходников, так и для установленной копии: source/target, грязный индекс/дерево, worktree, baseline, статусы проверок/находок, отсутствующая/повреждённая квитанция и CLI record/verify.
- Штатный `skill-creator/scripts/quick_validate.py` и метаданные UI — PASS. Для валидатора установлен PyYAML 6.0.3 в изолированное локальное окружение `.local/`; сам навык и его инструмент используют только стандартную библиотеку Python и Git.
- Ручной анализ Python и инструкций: argv без shell, отсутствие eval/exec/сети/merge, строгий отказ при непрошедших обязательных проверках, отсутствие исполнения содержимого JSON; вывод Git stderr и пользовательских значений не раскрывается. Ограниченный поиск шаблонов приватных ключей/GitHub/AWS credentials в новых материалах — совпадений нет; это не полный анализ секретов и истории.
- Специализированные gitleaks/Bandit/Semgrep/pip-audit недоступны и не запускались. Для небольшого инструмента на стандартной библиотеке применены ручной анализ и целевые тесты; приложения, runtime-зависимостей и CI в этой итерации нет. Полный аудит будущего приложения не заявляется.

Документация проверяется `python3 scripts/verify_docs.py`, включая отдельную копию переносимого комплекта без `.local/`; финальный diff и staged diff проверяются перед коммитом. Полные фактические логи и сведения установки хранятся локально. После финального коммита локальный pre-merge отчёт/квитанция привязываются к полученному source SHA; непосредственно перед последующим разрешённым merge verify необходимо выполнить снова.
