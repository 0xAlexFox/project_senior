# IT-0027 — Общие Select и аудит отступов

Дата: 27 ноября 2026 г. Основание: владелец указал на стрелку направления у самого края и поручил пройти проект на похожие несоответствия. Дополнительным прямым поручением «отмени изменения в файле в результате сторонней правки» разрешил восстановить docs/frontend-verification.md.

## Изоляция и область

Режим Б, один исполнитель без субагентов, продолжение `feature/frontend-completion` от `82eb4e9`, target `main`, папка project_senior. Исходная сторонняя правка frontend-verification удаляла поясняющий абзац, а не таблицы; по поручению владельца файл восстановлен из HEAD, docs-проверка PASS. Это не отдельный непустой коммит, так как tracked-версия не менялась. Последующие дополнения файла относятся к результатам IT-0026/0027. Merge/push не разрешены.

Область аудита — текущий frontend: 59 файлов src после добавления двух SVG, 12 семейств страниц (7 публичных, стенд компонентов и 4 страницы кабинета), общие поля/иконки/диалоги, обе темы и узкий экран. Backend/DB/runner не существуют и в аудит интерфейса не входят. Это проверка указанных визуальных свойств, не полный попиксельный аудит 194 кадров Pixso или аудит безопасности всего проекта.

## Подтверждённые находки и исправления

1. В select.control резерв 40 px управлял текстом; браузерная стрелка игнорировала этот отступ и оказывалась у края. Pixso подтверждает 12×6 px и отступ 24 px у 12 выборов направления. Appearance none и общий декоративный SVG с семантическим цветом темы теперь дают тот же контур; резерв текста 48 px, SVG 16×16 с background-position right 21 px при border 1 px. По растровому снимку Chrome в обеих темах измерены ширина контура 12 px и правый отступ 24 px. Изменение единое для направления, фильтров, часового пояса, стенда и учебных настроек. Нативный select, подписи, значения/обработчики и popup сохранены. В forced-colors возвращены appearance auto/background none.
2. У disabled-полей оставался cursor pointer. Для control:disabled установлен not-allowed; штатное затемнение не менялось (Chrome opacity 0.7). Проверено в обеих темах. Логика disabled не изменена.
3. Общий focus-visible имел outline-offset 4 px при проектном правиле 3 px; исправлен до 3 px. После смены маршрута неинтерактивный h1 с tabindex=-1 получал прямоугольную рамку: она убрана только для этого программного фокуса. Фокус на h1 сохраняется, Tab и рамки полей/кнопок не отключены.
4. В Pixso Select/default содержал текст «PDF ↓» вместо самостоятельного индикатора; у четырёх полей часового пояса индикатор отсутствовал. Master получил отдельную стрелку, padding и responsive stretch/grow; часовой пояс — такую же стрелку.
5. Четыре группы файловых фильтров Pixso представляли выбор кнопками, а mobile не содержал сортировку. Они заменены 12 экземплярами Select/default с подписями «Формат», «Источник», «Сортировка», значениями сохранённого сценария; desktop — три колонки с gap 16 px, mobile — вертикально. Поток следующих элементов/высота кадров пересчитаны. Триггеры реальных dropdown в приложении уже существовали и не менялись.

## Pixso и визуальная проверка

Использован штатный MCP: baseline, eval_script и повторные снимки. Две первые операции чтения/подготовки выявили особенности Auto Layout: координата стрелки игнорировалась внутри горизонтального поля, resize экземпляра не растягивал фиксированных потомков. Сервер вернул rollback; после каждого сбоя фактически перечитана восстановленная структура. Исправлены padding/flow master, stretch внешних детей и grow значения; повторный readback подтвердил отступы (допуск float 0.02 px). Контроль итогового числа экземпляров также выявил оставшийся после rollback собственный пробный экземпляр 34:242 на корне Desktop; он удалён точечно после проверки ID/типа/исходного компонента, итоговый счётчик 820 подтверждён. Без сброса всех overrides и без detaching компонентов.

Просмотрены master dark/light и направление, затем dark desktop-фильтры, light mobile-фильтры и часовой пояс. Спецификация и две подписи основы — версия 1.7. Ожидаемый состав: 194 корневых кадра / 34 компонента / 820 экземпляров (на 2 больше из-за mobile-сортировки); итог подтверждается повторным чтением.

## Проверки

Browser plugin/browser skill отсутствуют; аудит через установленный Playwright Chrome. Статический инвентарь зафиксирован в .local/control-audit. Обход — 192 режима: 12 семейств × 360/390/768/1440 px × dark/light × 100/200% текста. Выполнены 320 проверок полей (96 Select) и 592 проверок встроенных иконок; это повторные наблюдения в режимах, не число уникальных элементов. Проверены title/main, отсутствие Vite overlay/console/pageerror/overflow, высота/внутренние отступы полей, оформление Select и попадание иконок в контейнеры. Окончательных находок по этим геометрическим условиям — 0. Сохранены 48 снимков страниц при 390/1440; это не означает визуальное чтение каждого пикселя всех снимков.

Отдельный interaction-сценарий в обеих темах: смена направления → фильтр файлов → часовой пояс; подтверждены значения/URL, focus-снимки и реальный Tab (рамка 2 px / offset 3 px), сохранение фокуса h1 без рамки, disabled и forced-colors. PNG снимок загружался в canvas только для измерения контура, изображения не редактировались. Просмотрены focus направления dark, фильтры light, disabled dark, а также выборочные полные страницы. Проверочный сценарий уточнён: служебный маршрут /preview/components; его демонстрационный skeleton намеренно видим; скрытые children закрытого details не учитываются. Vite встраивает маленький SVG в data URL — проверяется реальный цвет, а не имя ресурса. Эти исправления сценария не являются исправлениями приложения.

Нет новых входов/операций, зависимостей или API. SVG статические, без scripts/ссылок; CSS не меняет поток данных и обработку секретов. Новые trust boundaries N/A; регрессионная проверка чувствительных форм остаётся в полном E2E. Другие браузеры/физические устройства, физический popup ОС и полноценный screen reader не проверялись; системный popup сохраняется намеренно. Ранее известные ограничения предварительного frontend остаются.
