# IT-0001 — Git-процесс и подготовка нового проекта

Дата — 18 ноября 2026 г.
Поисковые слова — git-commit, инициализация, подготовка проекта, ветки, ревью.

## Задача и решение

Владелец попросил дополнить памятку запуска нового проекта правилами применения установленного `git-commit` и применить навык к project_senior, где Git отсутствовал.

Проверка preflight подтвердила отсутствие репозитория, проверка родительского каталога — отсутствие внешнего репозитория. `docs/git-flow.md` отсутствовал. Выбран режим Б, один исполнитель в `/Users/alex/Обучение/project_senior`, исходный HEAD и индекс отсутствовали. Рабочая ветка — `chore/git-setup`, целевая — `main`, пока отсутствует. Существующая Git identity использована без изменения конфигурации. Просмотр процессов через `ps` недоступен из-за ограничения среды, сведения о другом исполнителе в этой папке отсутствовали.

Первый локальный коммит сохраняет существующие проектные документы, OpenAPI, основу и референс как исходное состояние вместе с новым Git-порядком. При первой разрешённой интеграции потребуется создать `main` на проверенном результате и перейти в неё.

## Карта изменений

- `заметки/подготовка-нового-web-проекта-с-codex.md` — версия 0.2, раздел 5.1 с подключением навыка до генерации, сценариями состояний Git, проверками, журналом и ревью. Промпт разрешает локальную инициализацию и проверенные коммиты, содержит порядок интеграции.
- `AGENTS.md` — автоматическое применение навыка и краткие правила проекта.
- `docs/git-flow.md` — ветки, проверки, журнал, формат коммитов и разрешение интеграции.
- `.gitignore` — исключение для сохранения обновлённой памятки в истории. Остальные личные заметки исключены.
- `docs/history/` — индекс и запись первой итерации.

## Проверка

- `python3 /Users/alex/.agents/skills/git-commit/scripts/preflight.py /Users/alex/Обучение/project_senior` до инициализации — exit 0, repository false.
- `git init -b chore/git-setup` — exit 0 после запроса расширенного доступа к `.git`, обычная sandbox-команда получила Operation not permitted.
- `python3 .local/git-setup/verify.py` — PASS, проверены заголовки и парность блоков Markdown, существование файлов по относительным ссылкам, синтаксис JSON, выбранные шаблоны секретов и правила исключений. Исходная `основа.md` имеет свободное оформление, требование H1 применяется к остальным документам.
- `git diff --cached --check` — exit 0. Проверены состав и статистика индекса, содержание новых инструкций. Фактический итог сохраняется в локальном отчёте `.local/git-setup/verification.md`.

## Ограничения и продолжение

Четыре ссылки ведут к существующим локальным файлам, исключённым из Git. README и план ссылаются на прежний `.local/spec-v02/verification.md`, памятка — на две соседние личные заметки. В чистом клоне эти материалы потребуется предоставить отдельно. Исходные личные заметки и прежний локальный отчёт сохранены в рабочей папке.

Итог передаётся владельцу на ревью. Следующий Git-шаг — создание отсутствующей `main` на представленном коммите после прямого текстового «Да, сливай» на этот результат и действие. Удалённые операции требуют соответствующего разрешения задачи.
