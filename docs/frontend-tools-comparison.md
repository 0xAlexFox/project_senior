# Почему не другие frontend-инструменты

18 ноября 2026 г. · Справочный материал для ознакомления.

Блок перенесён из [выбора технологий](technology-decisions.md) без изменения содержания.

| Вариант | Оценка для этого проекта |
| --- | --- |
| Vue + Vite | Основной выбор: приложение с формами и серверными задачами, небольшой кабинет, знакомый JavaScript |
| Nuxt | Рассмотреть, если привлечение через поиск станет основным каналом и понадобятся десятки индексируемых страниц конвертации. Сейчас SSR не решает очередь/изоляцию и усложняет старт |
| React + Vite | Технически подходит; выигрыша для текущих требований не видно, переучивание добавляет работу |
| Angular | Возможен, но больше соглашений и обязательный TypeScript при небольшом объёме продукта |
| Astro | Хорош для преимущественно контентного публичного сайта; кабинет/прогресс всё равно требуют интерактивного приложения |
| Чистый JavaScript | Можно, но на наборе форм/маршрутов/общих состояний Vue снижает объём ручной синхронизации |

Это сравнение пригодности, не утверждение, что остальные инструменты неспособны выполнить задачу. TypeScript не добавляется в исходное предложение: для обучения сохраняем JavaScript, JSDoc и runtime-схемы API. Если проект превращается в командный продукт, TypeScript полезно отдельно оценить; он не заменяет проверку реального файла и ответов API.

### SEO

Кабинет и личные файлы закрыты, поисковая индексация им не нужна. Для публичного конвертера и документации SEO может быть важным каналом привлечения — одностраничность сама по себе не делает SEO ненужным. В MVP предусмотрены метаданные и семантика, но для предсказуемой индексации содержимого/социальных превью маршрутов понадобится предрендеринг публичных страниц либо Nuxt. Не обещать полноценное SEO простой сменой document.title в SPA. Решение зависит от маркетинговой задачи, которой в основе нет.
