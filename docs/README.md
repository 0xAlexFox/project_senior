# Навигация и правила документации

## Порядок чтения

Основной порядок чтения и матрица зависимостей находятся в [корневом README](../README.md#порядок-чтения). Документы `01`–`08` — спецификации и обоснования; [tasks](tasks/00-technical-spike.md) — инструкции этапов будущей реализации; [history](history/README.md) — журнал выполненной работы.

Дополнительные документы: [дизайн продукта](../DESIGN.md), [макет Pixso](pixso-mockup.md), [темы](themes.md), [Git-процесс](git-flow.md).

## Имена файлов

- Спецификации: `NN-english-kebab-case.md`, например `01-product-requirements.md`. Номер задаёт порядок чтения, сохраняется при переименовании и не обозначает готовность реализации.
- Задачи: `tasks/NN-english-kebab-case.md`, например `00-technical-spike.md`; номер соответствует стабильному идентификатору TASK-00–06.
- Справочники и отчёты: `english-kebab-case.md`, например `pixso-mockup.md` и `git-flow.md`.
- Журнал: `history/IT-NNNN-english-kebab-case.md`. Префикс IT и номер — стабильный идентификатор итерации, поэтому регистр сохраняется.
- `README.md`, корневые `DESIGN.md` и `AGENTS.md` сохраняют общепринятые имена. Английские имена файлов не меняют русский язык содержания и интерфейса.

Единого обязательного стандарта имён для всех приложений нет: это соглашение данного репозитория. Переименование сопровождается обновлением ссылок во всех отслеживаемых документах, инструкциях и проверках. Старые дубли не сохраняются; прежние пути доступны в Git-истории.

Исходная `основа.md` и личные материалы в `заметки/` находятся вне нормализации каталога docs: оригинал задания сохраняется, личные заметки подчиняются `.gitignore`.

## Текущее состояние и история

Спецификация описывает требуемое поведение, задача — условия её будущего начала и завершения, отчёт — фактически выполненные проверки. Записи history отражают состояние на момент соответствующей итерации; их прежние количества, ветки и результаты не являются текущим статусом проекта. После изменения состояния добавляется явное уточнение или ссылка на новый отчёт, исторические результаты проверок не переписываются задним числом.
