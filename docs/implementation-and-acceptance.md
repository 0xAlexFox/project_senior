# Критерии приёмки

Версия 0.3 · 24 ноября 2026 г. Это план будущих проверок, а не отчёт об уже работающем приложении.

## 1. Этапы

Последовательность, зависимости, работа, результаты и критерии завершения всех задач находятся в [едином плане выполнения работ](work-plan.md). Здесь сохраняются сценарии приёмки AC-01–30 и соответствие исходной основе.

## 2. Проверяемые сценарии

| ID | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| AC-01 | JPEG с EXIF-ориентацией → PNG | Ориентация верна, разрешение соответствует ориентированному исходнику, метаданных нет |
| AC-02 | PNG с alpha → JPG | Белый фон, предупреждение до старта, один кадр, JPEG MIME |
| AC-03 | DOCX: кириллица, таблица, изображения, колонтитулы; PDF на границе числа страниц и выше | Читаемый PDF, текст извлекается, ожидаемое число/геометрия страниц; 200 страниц допускаются, 201 даёт FILE_COMPLEXITY_EXCEEDED |
| AC-04 | Изменение расширения exe/ZIP на jpg/docx | Отклонение по сигнатуре/структуре, ничего не исполняется |
| AC-05 | Ровно 10/20 MiB и на байт больше | Граница допускается при валидном содержимом, превышение 413 |
| AC-06 | 0 байт, 2 файла, повтор полей/неизвестное поле | Безопасный 400, временные данные очищены |
| AC-07 | Валидные изображения и DOCX разных размеров/структуры в пределах входного лимита; отдельно APNG и исчерпание ресурсов runner | Нет отказа только из-за числа пикселей/длины стороны или распакованного объёма/числа элементов/сжатия DOCX. APNG отклоняется как неподдерживаемый формат. Исчерпание ресурсов завершает попытку контролируемой ошибкой; тайм-аут — CONVERSION_TIMEOUT |
| AC-08 | Зашифрованный DOCX, макросы/внешние связи/OLE | Контролируемая ошибка, сеть не используется, программа не зависает |
| AC-09 | Двойное нажатие/повтор с тем же UUID | Один job и один резерв квоты; конфликт другого тела — 409 |
| AC-10 | Ответ POST потерян после commit | Повтор восстанавливает существующую задачу; квота не списана второй раз |
| AC-11 | Падение worker после записи output до commit | Повторная доставка не публикует два файла; старый lease не перезаписывает результат |
| AC-12 | Очередь/тайм-аут/сбой storage | Соответствующий код, нет ложного success и бесконечных попыток |
| AC-13 | Отмена одновременно с завершением | Либо succeeded+409 отмены, либо cancelled без доступного позднего файла |
| AC-14 | Save=true, затем выключение во время работы | Первая задача сохранена; следующая временная; старая библиотека не удалена |
| AC-15 | API передаёт явный save=false при общей true | Только этот результат временный; настройка пользователя не меняется |
| AC-16 | Два задания почти заполнившего квоту аккаунта | Атомарные резервы не допускают превышения; без молчаливой смены сохранения |
| AC-17 | Истечение часа/удаление/повтор скачивания | Доступ закрыт независимо от задержки физической очистки; чужому 404 |
| AC-18 | Попытка A прочитать/отменить/удалить файлы B | Нет содержимого/метаданных B, одинаковый безопасный 404 |
| AC-19 | Нет/неверный/отозванный API-ключ; только cookie на /v1 | 401 до обработки файла; нормальный ключ разрешает только свои операции |
| AC-20 | Замена/отзыв ключа и потеря ответа выпуска | Старый не работает; повторного раскрытия секрета нет; есть явный новый выпуск |
| AC-21 | Поддельный CSRF/Origin, истекшая сессия | Нет изменения данных, понятный вход/ошибка, секретов в ответе нет |
| AC-22 | Новый чужой Telegram username на восстановлении | Не принимается; сообщение только в ранее подтверждённый chat ID |
| AC-23 | Просроченный/повторный/перебранный recovery code | Отклонение, лимиты, нейтральные ответы; один код не применяется параллельно дважды |
| AC-24 | Telegram недоступен / потерян | Доступен ранее выданный резервный код; без обоих факторов нет обхода проверки |
| AC-25 | Сброс пароля/удаление аккаунта во время конвертации | При сбросе отозваны сессии/ключ; при удалении запоздавший результат уничтожен |
| AC-26 | Потеря сети/смена страницы/reload | Нет дублей, принятая задача восстанавливается; незагруженный File после reload предлагается выбрать заново |
| AC-27 | Два редактора настроек/профиля | Устаревшая версия даёт 409; чужие изменения не затираются |
| AC-28 | 360 px, 200% текст, клавиатура, длинные имена | Нет перекрытий/обрезанных действий, видимый фокус, ошибки связаны с полями |
| AC-29 | Backup и восстановление в отдельную среду | Метаданные/файлы согласованы, удалённые объекты не воскресли, checksum совпали |
| AC-30 | Логи, bundle, репозиторий и примеры API | Нет реальных токенов/паролей/файлов; примеры используют заглушки |

Для тестов только искусственные документы/изображения. Не отправлять приватные файлы сторонним сервисам. Повреждённые и опасные fixtures хранить безопасно, с описанием, не исполнять. Нагрузочные цели REQ-20 измеряются на записанном стенде; результат на локальном Mac не выдаётся за production-измерение.

## 4. Что проверено при подготовке документов

Для исходной версии прочитана основа и визуально изучен прежний референс; уточнения помечены предложениями. С 19 ноября 2026 г. оформление определяет [описание макета](mockup-specification.md), заменившее удалённый владельцем референс; макет проверяется по его критериям и сценариям документа экранов. Проверены локальные ссылки, JSON-синтаксис/внутренние `$ref` OpenAPI, состав методов/статусов и согласованность базовых лимитов. Подробный отчёт проверки версии 0.2 находится локально в `.local/spec-v02/verification.md` вне Git; он не входит в переносимый комплект. Текущее состояние и пределы выполненных проверок отражены в [статусе проекта](project-status.md), исторические результаты — в [журнале](history/README.md).

Не выполнены и не объявляются выполненными: запуск приложения, установка зависимостей, интеграция Telegram, конвертация файлов, проверка sandbox, нагрузка, браузерные тесты. Эти работы относятся к следующим этапам.

Первая визуальная версия макета Pixso создана 19 ноября 2026 г.; её отдельные проверки и ограничения описаны в [отчёте](mockup-specification.md#13-текущий-состав-файла-pixso).

Дизайн поддерживает тёмную и светлую темы: все 96 кадров имеют варианты, цвета связаны с режимами коллекции Pixso. В TASK-05 отдельно проверить контраст текста, границы полей, ошибки, активные/неактивные действия и фокус в обеих темах на desktop и mobile. Проверка статического макета не заменяет эти проверки работающего интерфейса. [Инструкция по темам](themes.md).
