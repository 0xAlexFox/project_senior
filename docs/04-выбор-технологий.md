# Анализ ТЗ и выбор технологий

Версия 0.2 · 17 ноября 2026 г. · Основание: [ТЗ](01-техническое-задание.md), [экраны](02-экраны-и-сценарии.md), [API](03-api.md).

## 1. Вывод

Рекомендована связка **Vue 3 + JavaScript + Vite + Vue Router; Node.js + Fastify; PostgreSQL + pg-boss; Sharp и LibreOffice в изолированном runner**. Файлы — в приватном дисковом хранилище первого развёртывания, с интерфейсом для последующего перехода на объектное хранилище.

Это небольшое приложение по числу экранов, но не только frontend: для закрытых файлов, API-ключей, восстановления доступа и безопасной обработки документов нужен настоящий backend. Самая рискованная часть — приём чужих DOCX и управление файлами/правами, а не выбор между Vue и React. Отдельная очередь нужна уже в MVP, чтобы LibreOffice не держал HTTP-запрос и переживал закрытие вкладки.

Решение не требует платного API конвертации. Сервер, домен, резервные копии и эксплуатация всё равно имеют стоимость; документация не обещает бесплатный промышленный хостинг.

## 2. Технологии и их ответственность

| Слой | Выбор | Почему подходит | Ограничение |
| --- | --- | --- | --- |
| Интерфейс | Vue 3, Composition API, `<script setup>`, JavaScript | Декларативные формы, состояния задач и знакомый учебный подход | Сам по себе не реализует серверную авторизацию/конвертацию |
| Сборка | Vite 8, совместимый официальный Vue plugin | Достаточно для SPA, быстрый dev и отдельный production build | Dev/preview не являются публичным backend |
| Навигация | Vue Router 4 | У кабинета, восстановления и документации отдельные URL | Закрытый маршрут UI — только удобство; реальные права проверяет API |
| Состояние | composables + общий session/job state | File остаётся в памяти при переходе на вход; нет лишнего глобального хранилища | При росте количества независимых разделов пересмотреть необходимость Pinia |
| HTTP клиента | fetch; XMLHttpRequest для измеримого upload progress | Не нужна дополнительная HTTP-библиотека | Отмена клиентского ожидания не равна отмене серверной задачи |
| Формы и стили | Нативные элементы, CSS variables, небольшие свои компоненты | Можно воспроизвести референс без большого UI-kit | Доступность диалогов/фокуса нужно проверять вручную и тестами |
| Сервер | Node.js 24 LTS, Fastify 5, ES modules | Один основной язык, схемы входа/выхода, маршруты и плагины | CPU-тяжёлая конвертация вынесена из процесса API |
| Multipart | Совместимый `@fastify/multipart` | Потоки и жёсткие лимиты | Нельзя собирать все загрузки в Buffer; важно дочитывать/прерывать части корректно |
| Данные | PostgreSQL 18, `pg`, SQL-миграции | Транзакции, уникальность логина/ключей, конкурентные квоты и очередь | Требует резервирования и проверки восстановления |
| Фоновые задачи | pg-boss 12, та же PostgreSQL | Нет отдельной Redis только ради одной очереди; постановка в общей транзакции | Задачи идемпотентны; файловые эффекты не становятся транзакционными автоматически |
| Изображения | Sharp 0.35 | JPEG/PNG, ориентация/цвет/метаданные | Нативные библиотеки и память; нужны актуальные патчи и ограничения |
| Документы | LibreOffice 26.8 headless, фиксированные шрифты | Локальный DOCX → PDF без внешнего сервиса | Совместимость с Word не идеальна; обязательны реальные fixtures |
| Пароли | Argon2id, поддерживаемая Node-библиотека | Специализированное хеширование паролей | Стоимость хеша подобрать измерением; минимум OWASP — отправная точка, не оптимизация вслепую |
| Приватные результаты | Файловый storage adapter на постоянном volume | Достаточно одному серверу, недорого в сопровождении | Для нескольких worker-хостов перейти на S3-совместимый backend |
| Telegram | Bot API через серверный адаптер | Восстановление без почтового провайдера | Внешняя зависимость, пользователь должен начать диалог; нужен запасной путь |
| Контракт | JSON Schema маршрутов и OpenAPI 3.1 JSON | Проверка во время выполнения, понятные ошибки, документация интеграторам | OpenAPI в папке — проект контракта; он ещё не доказывает соответствие будущего сервера |
| Проверки | Node test/Fastify inject, Vitest + Vue Test Utils, Playwright | Бизнес-правила, UI и сквозные сценарии разделены | Движки требуют отдельных интеграционных проверок на Linux |

Проверенная документация Vue подтверждает SFC/Composition API; Fastify — полные JSON Schema и управляемую сериализацию; Multipart — потоковый разбор. Это технические возможности инструментов, а выбор их комбинации — вывод для данного ТЗ. [Vue](https://vuejs.org/guide/introduction.html), [Fastify](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/), [Multipart](https://github.com/fastify/fastify-multipart).

### Версии и воспроизводимость

У нового проекта ещё нет установленных зависимостей. В таблице указаны целевые стабильные ветки, не готовый lock-файл. Перед установкой проверить совместимость актуальных patch-версий, Node, Vite/Vue plugin, Fastify-плагинов и pg-boss. Затем сохранить package-lock, `.nvmrc`, точные версии движков/шрифтов и digest образа runner; повторная установка через `npm ci`.

На дату исследования официальный список Node указывает LTS и у 24, и у 26; 24 выбран как более устоявшаяся основа, а не как «последняя версия». PostgreSQL 18 поддерживается, рекомендуется его актуальный minor. Бета/RC не брать автоматически. [Node releases](https://nodejs.org/en/about/previous-releases), [PostgreSQL versioning](https://www.postgresql.org/support/versioning/).

## 5. Источники и пределы технических выводов

Изучены официальные материалы и документация через Context7; никаких библиотек/движков в новый проект не устанавливалось, конвертация реальных файлов не выполнялась.

- [Sharp: output](https://sharp.pixelplumbing.com/api-output/) и [constructor](https://sharp.pixelplumbing.com/api-constructor/) — форматы, метаданные и настройки преобразования. Эти возможности не доказывают безопасность произвольного файла без песочницы.
- [LibreOffice filters](https://help.libreoffice.org/latest/en-US/text/shared/guide/convertfilters.html) — DOCX-фильтры и `writer_pdf_Export`. Полноту визуальной совместимости можно подтвердить только набором документов.
- [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) — независимые проверки типа/имени, ограничения, приватное хранение и разграничение прав.
- [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) — специализированное хеширование паролей; [Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) — ограниченные одноразовые коды и нейтральные ответы. Конкретные сроки/количество кодов в ТЗ — предложения проекта.
- [Telegram deep linking](https://core.telegram.org/bots/features#deep-linking) и [Bot API webhook](https://core.telegram.org/bots/api#setwebhook) — начало привязки и секретный заголовок. Наш двухсторонний challenge — собственный сценарий, не готовая услуга восстановления Telegram.
- [HTTP 202](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/202) — принятие асинхронной задачи не равно успеху.
- [OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html) — формат контракта; файл проекта не содержит реализацию backend.

## 6. Реестр предложений, отсутствовавших в основе

Актуальный состав версии 0.2: ограничения пикселей/длины стороны изображения и параметров внутреннего архива DOCX удалены по согласованной правке. Остальные предложения сохраняются.

| Решение | Причина / когда пересматривать |
| --- | --- |
| JPG ↔ PNG, DOCX → PDF; без обратного PDF | Предсказуемый объём MVP; OCR и восстановление структуры PDF — отдельный продуктовый этап |
| Вход до запуска; без анонимных конвертаций | Контроль нагрузки/владения; если нужна конвертация без регистрации, отдельно спроектировать гостевые квоты и доступ |
| Один файл, без batch | Проще восстановление и ошибки; batch требует модели частичного успеха |
| Размеры/тайм-ауты/квоты ТЗ | Консервативная начальная конфигурация; уточнить по стенду и бюджету, не «зацементировать» в UI |
| Временный файл 1 час, постоянный до удаления | Отделяет «не сохранять в профиле» от возможности скачать результат |
| Резерв 50 MiB до начала сохранённой задачи | Надёжная квота при неизвестном размере выхода; при необходимости улучшить UX после измерений |
| Пароль + логин, Telegram опционален, резервные коды | Нет обязательной почты и зависимости от одного мессенджера; потеря всех факторов не обходится вручную |
| Полный API-ключ только при выпуске | Не хранить восстанавливаемый секрет ради повторного показа |
| Выключение save не удаляет прежнее; snapshot на приёмке | Прямое требование основы, устраняет гонку при смене настройки |
| Собственная реализация конвертации | Нет передачи документов стороннему платному провайдеру; ответственность за патчи/изоляцию остаётся у владельца |
| Linux для публичного запуска | Предсказуемые версии движков, шрифтов и ограничений; macOS — рабочая машина, не доказательство поведения сервера |
| Приватный диск + PostgreSQL | Достаточно одному хосту; горизонтальное масштабирование требует общего object storage |
| SPA без обязательного SSR | Разработка рабочего приложения; пересмотреть при явной SEO-стратегии |

Открытые решения перед развёртыванием: окончательное имя/домен; коммерческая цель/SEO; контакты и правила обработки данных; доступный сервер/диск и место backup; аккаунт и bot username Telegram; выбор поддерживаемого rootless runtime; фактическая переносимость LibreOffice/шрифтов; подтверждение лимитов по измерениям. Они не мешают проектировать интерфейс и API, но влияют на промышленный выпуск. Платные ресурсы и аккаунты автоматически не создавать.

## 7. Самопроверка ТЗ и главные риски

1. **Файлы могут быть больше/сложнее, чем кажутся.** Основа называла форматы небольшими; ТЗ не опирается на это предположение, проверяет размер потока и структуру формата, ограничивает ресурсы и время обработки.
2. **Сохранение/смена флага во время обработки.** Разрешено snapshot-правилом; старые файлы не удаляются.
3. **API-ключ в браузере.** Решено двумя контурами авторизации и общим внутренним сервисом задач.
4. **Потеря Telegram.** Есть заранее выданные коды; нельзя восстановить пароль по непроверенному username.
5. **Очередь и БД не гарантируют атомарность диска.** Нужны staging, leases, финальная публикация, очистка и тесты падений.
6. **Word → PDF не всегда визуально идентичен.** Ограничение описано до запуска; PoC на кириллице/таблицах/шрифтах обязателен.
7. **Технологии ещё не испытаны вместе.** До каркаса/публичного выпуска этап 0 проверяет движки, изоляцию и совместимость зависимостей. ТЗ готово для начала работы, продукт не объявляется производственно готовым.
