# Конвертер файлов — проектная документация

Версия 0.2 · 17 ноября 2026 г. · Рабочее название: «Конвертер».

Требования подготовлены по [основе](основа.md); оформление будущего продукта описано в [DESIGN.md](DESIGN.md), адаптированном из предоставленного текстового референса Dimension 19 ноября 2026 г. Это спецификация будущего приложения и обоснование архитектуры. Приложение, инфраструктура и макет в Pixso на этом этапе не создавались.

## Порядок чтения

1. [Техническое задание](docs/01-техническое-задание.md) — продукт, форматы, ограничения, авторизация, хранение и защита.
2. [Экраны и сценарии](docs/02-экраны-и-сценарии.md) — состав страниц, состояния и действия пользователя.
3. [Дизайн продукта](DESIGN.md) — палитра, типографика, компоненты, адаптивная композиция, состояния и план макета Pixso.
4. [Механизм API](docs/03-api.md) — загрузка, очередь, ответы, ключи, ошибки и примеры запросов.
5. [Выбор технологий и анализ ТЗ](docs/04-выбор-технологий.md) — рекомендуемый стек, риски и источники.
6. [План разработки и приёмка](docs/05-план-и-приёмка.md) — этапы, проверяемые сценарии и соответствие исходной основе.
7. [Архитектура приложения](docs/06-архитектура-приложения.md) — компоненты, потоки задач, изоляция, очередь, структура кода, первый сервер и выпуск.
8. [Модель данных](docs/07-модель-данных.md) — сущности, связи, транзакции и миграции.
9. [Задачи реализации](docs/05-план-и-приёмка.md) — отдельные инструкции TASK-00–06 и их зависимости.
10. [OpenAPI 3.1](api/openapi.json) — машиночитаемый контракт внешнего API `/api/v1`.

Решения, отсутствовавшие в основе и не согласованные отдельно, остаются предложениями; их реестр находится в документе выбора технологий. В версии 0.2 по согласованной правке удалены ограничения пикселей/длины стороны и внутреннего архива DOCX. Для загрузки сохраняются ограничения формата и размера: JPEG/PNG до 10 MiB, DOCX до 20 MiB. Лимиты результата, квоты хранения и ресурсы обработки задаёт ТЗ.

Для начала разработки достаточно этих Markdown-файлов и JSON. Дополнительные приложения для чтения и регистрации на сторонних площадках не нужны. В OpenAPI используется вымышленный домен `https://converter.example`; его необходимо заменить при настройке окружения. Реальных ключей, аккаунтов и пользовательских файлов в документации нет.

Исходная `основа.md` сохранена. Прежний визуальный референс удалён владельцем и заменён дизайн-спецификацией нашего продукта. DESIGN.md определяет оформление и подготовку Pixso-макета, документ экранов — поведение. Платные тарифы и AI-функции не входят в требования.

Справочно: [почему не другие frontend-инструменты](docs/08-сравнение-frontend-инструментов.md) — сравнение альтернатив и SEO для ознакомления.

## Зависимости и изменения

Каждый модуль отвечает за свою часть; ссылки используются вместо копирования архитектуры и модели данных в другие инструкции.

| Источник | Ответственность | Что обновлять при изменении |
| --- | --- | --- |
| ТЗ, REQ-01–20 | Продуктовые правила, лимиты, безопасность и сроки | Экраны, API/OpenAPI, архитектуру, модель данных, затронутые задачи и AC |
| Экраны | Страницы, действия и состояния | DESIGN.md, UI-задачи TASK-02–05 и соответствующие AC; при изменении поведения сначала ТЗ/API |
| DESIGN.md | Визуальные токены, компоненты, композиция и будущий макет | Визуальные указания экранов, TASK-05, кадры Pixso и будущую реализацию UI; поведение сохранять по ТЗ/API |
| API и OpenAPI | Контракты, конфигурация форматов, ошибки | Серверные/клиентские схемы, генератор контракта, TASK-01–05 и проверки примеров |
| Технологии | Выбор инструментов и обоснование | Архитектуру, TASK-00/01/06; менять версии после проверки совместимости |
| Архитектура приложения | Компоненты, изоляция, очередь, расположение кода, зависимости, состав релиза и сервер | Модель данных, API, каркас, инфраструктуру, README, TASK-00/01/03/06 и проверки отказов |
| Модель данных | Сущности, связи и сохранность | Миграции/repositories, API-схемы, TASK-01–04/06 и проверки конкуренции/восстановления |
| План и задачи | Порядок работы, входы и критерии завершения | Ссылки зависимых задач, соответствие REQ/AC и фактический журнал проверок |

При изменении общего правила сначала обновить его источник, затем все зависимые модули из таблицы. Численные пределы не задаются заново в задачах. TASK-00 → TASK-01 → TASK-02 → TASK-03 → TASK-04 → TASK-05 → TASK-06; полный список инструкций и их критерии доступны в плане.

Проверка документации версии 0.2: [отчёт](.local/spec-v02/verification.md). Реализация приложения в эту правку не входит.
